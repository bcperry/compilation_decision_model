### Decision Workflow and Operational Constraints *(mandatory when applicable)*

- Define `true`, `false`, error, and incomplete outcomes; only `true` starts localization.
- Define source/page evidence, rule validation/activation, and immutable rule-set identity.
- Define word boundaries, original-text offsets, context preservation, terminal spans,
  multiple-region handling, and unresolved attribution without assuming monotonicity.
- Require the same model/version, instructions, rule set, and inference configuration
  throughout a run; distinguish model-supported evidence from proven causality.
- Specify numeric input/file limits, model-call/retry/time budgets, and cancellation behavior.
- Specify authentication, authorization, retention/deletion, and sensitive-data handling.
- Define accessible UI states and measurable user-outcome acceptance criteria, not code
  coverage or test-count targets. A few outcome tests may satisfy multiple requirements.
- For unrelated features, explain which constraints are not applicable rather than
  silently omitting them. Resolve behavioral choices before affected implementation.
